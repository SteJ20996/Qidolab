# Just One More：新题型候选与初步相似玩法核查

日期：2026-10-13。状态：设计提案；没有把这些新玩法接入正式游戏菜单。Qidolab 是总品牌，原版栏目为 Think Again! / Dale una vuelta / 十八般脑洞，新栏目为 Just One More / ¡Una más! / 数字不打烊。

## 判断口径

我们可以独立编写规则组合、题目生成器、文案、视觉和程序；目前没有证据足以宣称下列任何玩法是全球首创。数学运算、排列、行列约束、反馈推理、延迟和时间回溯都是已有的设计材料。检索不到完全相同的组合，也不能证明不存在。

本轮按英文关键词寻找相近机制，并阅读开发者、发行商和官方商店的描述。没有审阅所有关卡，没有完成专利/商标/外观或全球法律清查。表中的“自己的特色”是设计判断，不是法律结论。所有候选英文名只是工作名称，尚未逐个查重。

美国版权局区分规则/系统/方法与受保护的具体表达。独立实现抽象规则不等于可以复制别人的代码、题库编排、说明、角色和美术；改数字也不是复制题目的通行证。资料：https://www.copyright.gov/help/faq/faq-protect.html 。其他权利的边界另见 `qidolab-2-provenance.md`。

## JOM-01：迟到一步

一句话：这一步点下去，上一回合才跟上。

- 桌上有两个数字 A、B 和 3–5 张一次性运算卡。
- 每次选一张剩余卡，并指定 A 或 B：先对选中的数字执行当前运算，再对上回合留下的那个数字执行“回声”。
- 当前卡会在下一回合对另一个数字再执行一次。界面始终显示待结算卡、它的目标，以及明确的先后顺序。
- 最后一张卡用完后，自动结算最后一个回声，再判断两个数字是否同时达到目标。不能在回声还没结算时宣布胜利。
- 本样题每个中间值都必须在 0–40 内；没有计时压力。实际产品用动画分开演示“现在”和“回声”，支持撤回整步。

独立样题：起点 A=2、B=7，卡片 +3、×2、−2 各一张，目标 A=6、B=15。

| 回合 | 新操作 | 结算上一步的回声 | 结算后 A、B |
|---|---|---|---|
| 1 | A +3 | 无 | 5、7 |
| 2 | B ×2 | B +3 | 5、17 |
| 3 | A −2 | A ×2 | 6、17 |
| 最后结算 | 无 | B −2 | 6、15 |

这道题有 2 条合法路线，全部接受。48 是 3! 种卡片顺序乘以 2³ 种目标选择，不代表难度评级。试算中排除了一种无效设计：若始终先结算旧回声再做新操作，两边会按同样顺序处理每张卡，很多选边操作失去意义。

生成方向：从随机合法路线造出目标，再枚举所有路线；筛掉选边不起作用、无需考虑回声、目标与起点相同的题。难度来自顺序依赖，不靠大整数。可研究“目标必须被回声最后完成”的进阶题，但先不要叠加额外规则。

相近机制：Calculator: The Game 已有数字操作序列；Silicon Zeroes 已有算术组件及状态/时序。因此可探索的特色是“两数字、交叉延迟、先新后旧、可见待办回声”的具体短局组合，而不是宣称发明了延迟运算。仅在本轮查看的资料中未确认完全相同的简化规则。

## JOM-02：线索串台

一句话：线索没有骗人，只是认错了主人。

- 给玩家四条已经提交过的猜测，以及四张反馈卡；卡片不再放在对应行旁边。
- 每张卡仍表示“正确数字总数 / 其中位置正确数”，规则沿用现有数字密码。
- 玩家可以把反馈卡配给猜测，再提交密码。允许临时错误配对、撤回和调整；不会隐性惩罚。
- 所有反馈必须真实。过关要求密码和反馈配对同时正确。若反馈卡完全相同，视为不可区分，不因交换同值卡判错。

独立样题：密码长 4 位，只用 0–5，数字不重复，首位允许 0。

| 已有猜测 | 等待配对 |
|---|---|
| 3025 | ? |
| 1452 | ? |
| 0245 | ? |
| 3140 | ? |

散落反馈卡：`2 / 0`、`3 / 1`、`3 / 2`、`4 / 2`。

答案为 `0425`。依上述行顺序，正确配对是 `3 / 2`、`3 / 1`、`4 / 2`、`2 / 0`。程序遍历 6P4=360 个可能密码，只发现这一个。

一个人工推理入口：有一张反馈说四个数字全对，因此密码的数字集合与某一行完全相同。比较这四种集合与其他行的交集大小，只有 `{0,2,4,5}` 能产生正确数为 `{2,3,3,4}` 的整组反馈。之后再推位置，避免只剩机械猜测。

生成方向：独立生成密码和猜测，计算真实反馈，再打乱整张反馈卡的归属；筛选密码唯一、可接受配对明确、线索有推理入口的题。绝不能只验证打乱前可解。先限制 0–5，再扩至 0–9，不直接用五位码堆复杂度。

相近机制：传统密码反馈推理及 Turing Machine 的验证式推理已经存在。CyberCode 的商店描述还提到打乱反馈指示；该简述不足以确认它是否跨猜测行打乱整组反馈，不能声称我们的差别已经证实。这里的设计重点是“整行反馈失去归属，联合推断答案和归属”，上线前还应进一步对比这一近似项。

## JOM-03：横竖两笔账

一句话：横着刚好，竖着又差一点。

- 固定 3×3 格子，每格有一对可见数字 `(横向贡献, 纵向贡献)`。
- 点击某格只交换这一对数字的位置，不移动格子，不改变数字本身。
- 每行只加各格的横向数，每列只加各格的纵向数；六个目标需同时满足。
- 例如一格显示“横 +2 / 竖 +5”，翻转后变为“横 +5 / 竖 +2”：这一行多 3，这一列少 3。
- 使用箭头和明确文字，不能只靠颜色区分横竖。新画自己的控件，不借用商业多米诺牌面。

样题数字对按行排列：

| 第一列 | 第二列 | 第三列 |
|---|---|---|
| (1,4) | (2,5) | (1,3) |
| (3,5) | (2,6) | (1,5) |
| (2,4) | (1,6) | (3,6) |

行目标：4、8、16。列目标：9、12、11。唯一解为翻转第二行第一格和第三行的三格，其余保持。遍历全部 2⁹=512 个朝向已确认。

这个样题只证明规则可解，第一行已经是最小和，属于暖身难度。真正的难关要筛掉大量一眼强制的格子，并验证是否仍有清楚的推理步骤。行列总贡献存在守恒关系，可做提示，但不能把它冒充独有规则。

相近机制：行列和、网格约束非常常见，Equate 8、Numix 等已有相关数字网格玩法。这里要尝试的区别是“固定格内两个数分别流向不同方向，翻转交换贡献”，不是普通移动数字补行列和。该区别尚未经过穷尽相似性核查。

## JOM-04：反着也得通

一句话：同一条路，两头都要走通。

把四张卡 `+4`、`×2`、`−3`、`×3` 排成一条指令带。A 从 3 出发，按左到右执行；B 从 8 出发，按右到左执行。目标分别是 16、63；每张卡在每台机器中各执行一次，禁止省略。样题中间数限定在 0–99。

唯一正确顺序：`×3 → −3 → ×2 → +4`。

- A：3 → 9 → 6 → 12 → 16。
- B：8 → 12 → 24 → 21 → 63。

程序枚举全部 4!=24 个排列，确认只有这个顺序成功。难关可增加一两张卡或少量禁入值，但先看四卡能否足够有趣。

相近机制：运算排列、函数复合和双目标编程谜题都有前例。它更适合作为自己设计的简洁组合玩法，不适合宣传成全新的数学机制。

## JOM-05：改一处，救全局

一句话：现在先别动，错在三步前。

显示两台机器用同一指令带运行的完整历史。只允许替换一个指定可编辑格中的运算卡，新卡必须从公开备选里选。替换后两条历史自动从该步开始重算：两个终点都要命中目标，且一个指定的中途检查点仍须满足原要求。

特色候选是“只准一处修改、两个起点同时受影响、检查点约束”。防止玩家只让其中一个终点正确。需要有演示重算、差异高亮和撤回；不能隐藏规则制造意外。

状态：没有生成或穷举样题。需先验证真的存在只能通过回溯关系理解的好题，而不是单个一元方程。时间回溯/修改过去已有大量前例（例如 Yesterlight），不能把该主题本身作为原创证据。

## JOM-06：借来的数字

一句话：先借你一下，过关之前记得还。

有一个当前值和有限运算卡。可以临时加上指定的借数 k，但之后必须减去相同的 k，且借和还各限一次。最终既要命中目标，又必须没有欠账。借还动作同样显示在历史里；乘法改变当前值，不改变记录在借条上的本金。

手算暖身：起点 2、目标 7，仅一张 ×2 卡，可以借 3。`2 + 3 = 5 → ×2 = 10 → 还3 = 7`。先乘再借还只能得到 4。

状态：只做了上述手算；未验证整套生成方案。这实质上接近额外 +k、−k 运算卡加先后约束，原创空间较小。若试玩没有出现明显不同于算 24 点的体验，就不独立开入口。

## 建议开发顺序与验收

先试 JOM-02，利用现有密码反馈引擎，快速检验“线索归属”是否有趣；同时用非常小的 JOM-01 演示验证延迟机制是否易懂。第二轮再试 JOM-03，补充视觉操作。JOM-04 可以作为较轻量的备选。

每个原型先做 3 道暖身与 7 道进阶人工挑选题，再开放生成器。自动生成至少要验证：有解；需要唯一答案的题确实唯一；所有合法路径都正确判分；提示不撒谎；撤回能恢复隐藏队列/借条/配对；切换语言不丢状态。用搜索深度、分支和人工试玩一起筛难度，不能只用最短步数。

随机数字空间有限，“无限玩”指可以不断生成和开始下一局，不承诺永不重复。最终仍要看真人试玩：规则是否能短时间理解，失败后是否愿意再试，以及重复局是不是只改了表面数字。

代表题验证脚本：`python3 docs/research/verify-concepts.py`。对应结果：`docs/research/concept-examples.json`。该脚本是可复现的概念检查，不是生产生成器、难度证明或权利清查。
